## Wiki Knowledge Base

Path: {{VAULT_PATH}}

When you need context not already in this conversation:

1. Read `wiki-meta/hot.md` first (cheap, recent context).
2. If hot.md doesn't cover it, read `wiki-meta/catalog.md` to find the relevant page.
3. Drill into specific wiki pages (user content lives under `wiki/...`).
4. After substantive work, append a 1-line entry to `wiki-meta/journal.md`.
5. After substantive work, refresh `wiki-meta/hot.md` with the latest state.

**Vault layout (v0.12.0+)**: scaffolding lives in `wiki-meta/` (the 4 files `hot.md`, `catalog.md`, `journal.md`, `overview.md` + the `Sessions/` journals), separate from user notes under `wiki/` (people, concepts, sessions, decisions, references, projects, …). This split makes the scaffolds (catalog + recent-context cache + operation log + executive summary) easier to spot in Obsidian and keeps the visible `wiki/` tree focused on real content.

**OKF projections (v0.59.0+)**: `wiki/index.md`, one `index.md` per content directory, and `wiki/log.md` are **GENERATED** navigation files (marker line `> Generated by obsidian-mcp-router`), refreshed automatically after writes. Three rules: never edit them by hand, never `[[wikilink]]` them (link `[[catalog]]`/`[[journal]]` instead — Obsidian resolves by basename and OKF reserves these two), and group related notes into subject directories (`wiki/<sujet>/`) — every directory gets its generated `index.md` landing page for human browsing.

**Always use the `obsidian-router` MCP tools for vault reads/writes** (`mcp__obsidian-router__get_file`, `mcp__obsidian-router__write_file`, `mcp__obsidian-router__patch_file`, etc.) — they're the multi-vault aware path and work cross-project. Do NOT use Claude's native `Read`/`Write` for vault content; those work only when the project IS the vault.

**Available wiki workflows** (slash commands or natural language):
- `/obsidian-router:wiki-ingest <source>` — file a source
- `/obsidian-router:wiki-query <question>` — answer from the wiki
- `/obsidian-router:save` — file the current conversation
- `/obsidian-router:wiki-lint` — health check
- `/obsidian-router:wiki-fold` — roll up the log
- `/obsidian-router:autoresearch <topic>` — autonomous research loop
- `/obsidian-router:canvas` — visual canvas operations

The wiki pattern (Karpathy LLM-wiki) is documented in `wiki-meta/overview.md`.

**Required frontmatter — `description`**: every page under `wiki/` MUST carry a one-sentence `description:`. This is not a style preference, it is a data contract: the generated directory indexes render `* [Title](file.md) - description`, so a page without one appears in the vault's own navigation as a bare filename, and `wiki-lint` reports it as a gap. Nothing synthesizes it for you — a missing description is reported, never invented.

That paragraph is the REQUIREMENT, and it ships with every scaffolded vault because the code applies it whether or not anyone opted in. How to write a good one — what to say, what to avoid, how long, how to quote it — is the separate `description-frontmatter` convention, which the conventions picker offers and which you can install at any time with `/obsidian-router:conventions install description-frontmatter`.
