Le routeur en 30 secondes

Un seul process MCP qui connaît tous tes vaults Obsidian (locaux + distants). Chaque outil prend un paramètre vault (ou utilise le défaut). Plus besoin d'enregistrer un MCP par vault.

  • Une entrée dans ~/.claude.json → tous les vaults visibles partout (Code + Desktop)
  • Vaults locaux + distants traités à l'identique — URL + clé API dans le config, point
  • Cross-vault : vault: "*" fan-out automatique sur tous les vaults
  • Lock mode : restreindre la session à un vault unique (sécurité, focus)
  • Auto-enrichment (v0.8.2) : Claude propose des saves au wiki à 3 moments (validation / résultat / changement de sujet)
  • Tags de confiance (v0.8.8) : source_type: extracted | inferred | claude_synthesized sur chaque page wiki — provenance lisible dans les citations de wiki-query ; helper sanitize.mjs anti-prompt-injection sur les réponses MCP
  • Scoring IDF + dynamic seed picking (v0.8.9) : wiki-query rank les pages candidates par IDF (exact ×1000, prefix ×100, substring ×1) avec cutoff dominant à 5× — fini les drills multi-pages bruyants
  • Conventions CLAUDE.md (v0.8.11) : 4 conventions installables (source-type, bilingual, heading-hierarchy, auto-enrichment) propagables cross-vaults via /obsidian-router:conventions install --all
  • Click-to-open (bridge v0.2.0) : liens cliquables dans le chat Claude Code via la route GET /open/<path> du plugin bridge — un click → Obsidian ouvre direct, plus de copy-paste

Setup d'un vault

  1. Avoir Node.js ≥ 20.18.1
  2. Installer le plugin Local REST API dans le vault Obsidian (community plugins)
  3. Optionnel pour search_smart : Smart Connections + obsidian-mcp-router-bridge (depuis GitHub)
  4. Optionnel pour Templater : Templater (community plugins)
  5. Bootstrap automatique du vault : 
    npm run setup-vault -- "C:\VAULTS\MonVault"
    ⇒ écrit .env avec VAULT_PATH, OBSIDIAN_API_KEY, OBSIDIAN_BASE_URL ; alloue un port unique ; ajoute au registry.
  6. Vérifier : /obsidian-router:meta-status ou demander « diagnostique le router »

Configuration — variables d'environnement (workspace .env)

VAULT_PATH Chemin du vault courant. Auto-détection : si match avec un vault enregistré, devient le défaut. Écrit par setup-vault.mjs.
OBSIDIAN_ROUTER_DEFAULT_VAULT Override explicite du vault par défaut pour ce process. Gagne sur VAULT_PATH et sur config.defaultVault.
OBSIDIAN_ROUTER_LOCKED Lock le router à un vault pour la session. Tout appel hors-vault throw. Set via /obsidian-router:lock <vault> --persist.
OBSIDIAN_ROUTER_AUTO_ENRICH Mode d'auto-enrichissement wiki : ClaudeAsk (défaut) | Hybrid | FullAuto | off. Set via /obsidian-router:auto-mode <Mode> --persist.
OBSIDIAN_ROUTER_NO_WATCH Désactive le hot-reload du fichier de config (utile pour debug).

Fichiers importants — où vivent quoi

~/.claude/obsidian-mcp-router/config.json Config principale du router (vaults, port registry, vault names, defaultVault, disabledVaults, remoteVaults). Hot-reload activé.
~/.claude.json Config Claude Code/Desktop. Doit contenir l'entrée mcpServers.obsidian-router pointant sur le binaire obsidian-mcp-router.
~/.claude/settings.json Active le plugin (extraKnownMarketplaces + enabledPlugins) et les hooks optionnels (SessionStart, PostCompact, Stop).
<workspace>/.env Variables d'env du workspace courant (ci-dessus). Auto-loaded au boot du router.
<vault>/CLAUDE.md Consigne wiki du vault — chargée par Claude Code dans le contexte. Inclut la consigne d'auto-enrichissement (4 modes) depuis v0.8.2.
<vault>/{index,log,hot,overview}.md Structure Karpathy LLM-wiki (catalogue, journal, cache chaud, vue d'ensemble). Scaffoldé par /obsidian-router:wiki.
obsidian-mcp-router/templates/wiki/CLAUDE.md Template canonique du CLAUDE.md de vault — cloné dans chaque nouveau vault scaffold.
obsidian-mcp-router/docs/auto-enrichment.md Guide complet auto-enrichment EN+FR : 4 modes (use cases) + 4 canaux de placement.
